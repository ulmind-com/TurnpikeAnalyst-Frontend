# Deployment Guide

Three deployables from one architecture: **Turnpike Frontend**, **Turnpike Admin**, and **Turnpike Backend**.

| Service | Platform | Monorepo Root Directory | Dedicated Repo Root Directory |
|---|---|---|---|
| **Turnpike Frontend** (`turnpike-frontend`) | Vercel Project 1 | `turnpike-frontend` | `turnpike-frontend` (`TurnpikeAnalyst-Frontend`) |
| **Turnpike Admin** (`turnpike-admin`) | Vercel Project 2 | `turnpike-admin` | `turnpike-admin` (`TurnpikeAnalyst-Adminpanel`) |
| **Turnpike Backend** (`turnpike-backend`) | Render Web Service | `turnpike-backend` | `.` (`TurnpikeAnalyst-Backend`) |

---

## 1. Turnpike Backend on Render

Import `TurnpikeAnalyst-Backend` (or connect the monorepo); Render reads `render.yaml`. Values marked `sync: false` are secrets and must be entered in **Environment** on the Render dashboard.

| Variable | Value |
|---|---|
| `MONGODB_URL` | MongoDB Atlas connection string |
| `CORS_ORIGINS` | Both Vercel URLs, comma-separated, no trailing slash |
| `SECRET_KEY` | Auto-generated by Render or strong random 32+ byte secret |
| `OPENROUTER_API_KEY`, `GROQ_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY` | At least one AI key is required |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | **Required in production** |
| `FIREBASE_CREDENTIALS_JSON` | Full Firebase service account JSON as one value |
| `GITHUB_TOKEN` | Optional; raises GitHub REST read limit from 60/hr to 5000/hr |
| `SUPER_ADMIN_EMAIL`, `SUPER_ADMIN_PASSWORD` | Bootstrap credentials for first startup (ignored once an `ADMIN` exists) |

**Cloudinary is required in production:** Render's filesystem is ephemeral — anything written locally disappears on the next deploy. Certificates, template artwork, diagram images, and intern `.zip` source archives are stored in Cloudinary.

In MongoDB Atlas, allow Render's outbound IPs under **Network Access** (or `0.0.0.0/0` if authenticated with strong database credentials).

## 2. Turnpike Frontend on Vercel

1. Import `TurnpikeAnalyst-Frontend` (or monorepo) in Vercel.
2. Set **Root Directory** to `turnpike-frontend`.
3. `turnpike-frontend/vercel.json` handles installing workspace dependencies from `..` so `@turnpike/shared` resolves cleanly and runs `NITRO_PRESET=vercel bun run build`.

| Variable | Value |
|---|---|
| `VITE_API_BASE_URL` | Render API URL, no trailing slash |

> **Important:** Set `VITE_API_BASE_URL` *before* building, because `VITE_*` variables are compiled into the client/SSR bundle at build time. Do **not** set a custom `outputDirectory` in `vercel.json` — Nitro emits `.vercel/output` in Build Output API v3 format automatically.

---

## 3. Turnpike Admin on Vercel

1. Import `TurnpikeAnalyst-Adminpanel` (or monorepo) in Vercel.
2. Set **Root Directory** to `turnpike-admin`.
3. `turnpike-admin/vercel.json` builds with `NITRO_PRESET=vercel` and sets `X-Robots-Tag: noindex, nofollow` and `X-Frame-Options: DENY`.

| Variable | Value |
|---|---|
| `VITE_API_BASE_URL` | Render API URL, no trailing slash |

---

## 4. Firebase Project Alignment

Google Sign-In connects two halves that must point to the **same** Firebase project (`turnpikeanalyst-ff936` by default):

| Side | Configuration |
|---|---|
| **Browser** (`turnpike-frontend`) | `packages/shared/src/lib/firebase.ts` (overridable via `VITE_FIREBASE_*`) |
| **API** (`turnpike-backend`) | `FIREBASE_CREDENTIALS_JSON` on Render |

---

## 5. Post-Deploy Checklist

1. Add both Vercel production URLs to `CORS_ORIGINS` on Render and redeploy.
2. Add both Vercel domains to **Firebase Console → Authentication → Settings → Authorized domains**.
3. Sign in to **Turnpike Admin** (`/login`), rotate the bootstrap password under **Administration → Sign-in & Security**, and upload & activate a certificate template under **Internship → Certificate Templates**.

---

## 6. Database Seeding & Cluster Migration

Run from `turnpike-backend/` (or repo root in `TurnpikeAnalyst-Backend`):

```bash
python -m scripts.seed_data          # users, services, courses, blogs
python scripts/seed_internship.py    # internship project briefs
python scripts/seed_chatbot.py       # support assistant knowledge base
```

> `scripts/seed_content.py` deletes `client_categories`, `industries`, and `blogs` before inserting — run only on an empty database.

To migrate between MongoDB clusters safely (upserts on `_id`, non-destructive):

```bash
MIGRATE_SOURCE_URL="mongodb+srv://..." python -m scripts.migrate_database --dry-run
MIGRATE_SOURCE_URL="mongodb+srv://..." python -m scripts.migrate_database
```
